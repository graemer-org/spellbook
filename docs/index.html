Shared spells for your AI coding agents

Keep your team's skills, instructions, agents, prompts, MCP servers and hooks in a git repository. Spellbook installs them into Claude Code, GitHub Copilot, Cursor, Codex and Gemini CLI, and keeps everyone up to date.

How it works

Write it once. Everyone gets it.

Your AI tooling lives in a normal git repository, the registry. Spellbook is the small command line tool that carries it to where each agent looks.

Put your spells in a repository

A folder with a SKILL.md is a skill. A Markdown file in instructions/ is an instruction. Agents, prompts, MCP servers and hooks work the same way.

Subscribe

spellbook registry add fetches the repository and writes every resource in the format each of your tools expects.

Stay in sync

spellbook sync installs what is new, updates what changed and removes what was deleted. With autosync it happens when a session starts.

Push back what you make

A skill that grew in a project? spellbook push puts it on a branch of the registry and hands you the pull request link.

What it syncs

Six kinds of spells, five tools

Each one is written once and translated per tool: file locations, frontmatter, even the model an agent uses.

{ }

Skills

Instructions and scripts the agent loads when a task calls for them.

#

Instructions

Standing guidance, always on or limited to certain files. Layered from company to team.

@

Agents

Specialists with their own prompt, tools and model, with per-tool settings where they differ.

>_

Prompts

Reusable tasks you start yourself, such as drafting release notes.

⇄

MCP servers

Connections to external tools and data. Installed only after you allow the registry to.

!

Hooks

Commands that run when something happens in a session. Also behind your permission.

Use cases

From one laptop to a whole company

The same spells on every machine

Subscribe to public collections, keep your own in a private repository, and let your tools pick up changes on their own.

  • Pick what you want from any repository with --skill.
  • Start your own registry with registry setup.
  • Forget about it: autosync runs at most once a day, in the background.
~
$ spellbook init
$ spellbook registry add anthropic \
    https://github.com/anthropics/skills --skill pdf --skill docx

# your own spells
$ spellbook registry setup ~/code/my-spells
$ spellbook registry add mine git@github.com:you/my-spells.git

$ spellbook autosync enable

Your private spells next to your company's

Subscribe to both. Each registry is its own git repository, so your private one stays private, and Spellbook keeps track of what came from where.

  • Company first: the registry with the higher --priority wins when two offer the same name, and its instructions are read first.
  • Nothing gets lost: with --prefix collisions your version of a clashing skill is installed too, as mine-<name>.
  • Prefer your own? Give mine the higher priority instead.
~
# your company's registry: standards and your team's tooling
$ spellbook registry add acme \
    git@github.com:acme/ai-registry.git \
    --group platform --priority 100

# your own spells, in a private repository
$ spellbook registry add mine \
    git@github.com:you/my-spells.git --prefix collisions

# see what is installed, and from which registry
$ spellbook list
NAME              KIND   TARGET  REGISTRY
code-review       skill  claude  acme
mine-code-review  skill  claude  mine
standup-notes     skill  claude  mine

$ spellbook autosync enable

Tooling that travels with the repository

Spellbook writes real files into the repository. Commit them, and teammates, cloud agents and GitHub workflows get the tooling with a plain git pull. Nobody else has to install anything.

  • Pinned: spellbook.lock records the exact commit of every registry.
  • Reviewed: diff shows what an update would change before you take it.
  • Guarded: sync --check fails CI when someone edits a synced file by hand.
my-repo
$ spellbook init --project
$ spellbook registry add acme \
    git@github.com:acme/ai-registry.git --project --group backend
$ git add spellbook.toml spellbook.lock .spellbook .claude .github
$ git commit -m "Add shared AI tooling"

# later: review and take an update
$ spellbook diff --project --patch
$ spellbook sync --project

# in CI
$ spellbook sync --project --check

Company standards, team tooling, reviewed like code

One registry holds everything, sorted into groups. A team's group includes the company baseline, and people join the groups of the teams they work with.

  • Onboarding in three commands: install, subscribe, enable autosync.
  • Change control you already have: pull requests, CODEOWNERS, a stable branch for staged rollouts.
  • Layering: combine a company and a team registry with --priority.
  • Access: whoever can clone the registry can subscribe. Nothing else to set up.
registry.toml
default_groups = ["base"]

[groups.base]
instructions = ["company-standards", "security-basics"]
skills = ["code-review", "commit-style"]

[groups.platform]
include = ["base"]
skills = ["terraform-review"]
agents = ["infra-reviewer"]
mcp = ["internal-docs"]

# on each machine
# $ spellbook group join acme platform

Careful by design

It only touches what it installed

A tool that writes into your agents' configuration has to be predictable. These rules hold for every command.

Your own files stay yours

A skill, rule or hook you created yourself is never overwritten or deleted, even when a registry offers one with the same name.

Local edits are kept

Something you changed after a sync is left alone, with a warning. Only --force overwrites it.

Code needs your permission

MCP servers and hooks run programs. A registry installs them only after spellbook registry allow.

A failed fetch removes nothing

When a registry cannot be reached, everything it installed stays in place and the command says so.
